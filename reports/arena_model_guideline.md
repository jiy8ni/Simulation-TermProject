# Arena 모델 만들기 가이드 — 교차로 15·16

이 문서는 **Arena를 처음 보는 팀원도 그대로 따라 만들 수 있도록** 쓴 설명서입니다.
교차로 15(시청사거리)와 16(관평사거리), 두 개의 사거리를 컴퓨터 시뮬레이션으로 재현합니다.

> 어려운 결정의 배경은 계획서 `quirky-mixing-yao.md`에, 데이터를 만드는 코드는 `src/13~16`에 있습니다.

---

## 먼저, 이 문서에 나오는 말들 (용어 미리 보기)

| 용어 | 쉬운 뜻 |
| --- | --- |
| **진입로** (leg) | 사거리로 **들어오는 한쪽 도로**. 사거리니까 한 교차로에 진입로가 4개(동·서·남·북). |
| **이동류** (movement) | "**어느 진입로에서 + 어느 방향(좌회전/직진/우회전)으로** 가는 차량 무리". 진입로 4개 × 방향 3개라서 한 교차로에 최대 12개, 두 교차로 합쳐 21개. |
| **도착률** | 1분(또는 5분)에 차가 몇 대 들어오는지. |
| **신호 시차** (offset) | 두 교차로의 초록불이 **켜지는 시점 차이**. 이게 잘 맞으면 차가 안 멈추고 쭉 지나감(연동). |
| **차량 군집** (platoon) | 앞 교차로 신호에 묶였다가 **떼지어 몰려오는** 차들. |
| **Create / Assign / Hold / Process / Dispose** | Arena의 기본 블록들. 바로 아래에서 설명. |
| **DISC(...)** | Arena 함수. **정해둔 확률대로 값을 뽑아주는** 주사위라고 보면 됩니다. |
| **1단계 모델** (Tier 1) | 우리가 만들 **가장 단순하고 확실한 버전**. 두 교차로를 한 화면에 두지만, 차를 한 교차로에서 옆 교차로로 직접 넘기진 않습니다(이유는 맨 아래 9절). |

### Arena 블록이 하는 일 (한 줄 요약)
- **Create**: 차를 만들어 낸다(도착 발생).
- **Assign**: 차에 속성을 붙인다(회전 방향, 차종 등).
- **Hold (Wait for Signal)**: **빨간불이면 세워두고 초록불에 보낸다.**
- **Process**: 교차로를 빠져나가는 데 걸리는 시간을 표현(자원 잡고 → 잠깐 머물고 → 놓아줌).
- **Station / Route**: 차가 지나는 **지점**과 **경로**(화면에서 움직이게 하는 부분).
- **Dispose**: 차가 빠져나감(소멸).

---

## 우리가 만드는 모델, 한눈에

- 한 사거리에는 **진입로가 4개**, 진입로마다 **차가 들어와 → 신호를 기다렸다 → 빠져나갑니다.**
- 차마다 회전 방향(좌/직/우)과 차종(승용/버스/화물 등)을 확률로 정해줍니다.
- 두 교차로를 한 모델에 같이 놓고 **같은 시계(0초 = 오전 8시)** 를 씁니다. 그러면 두 교차로의
  실제 신호 시차가 그대로 살아납니다.

### 차 한 대가 거치는 길 (한 진입로 기준)

```
[들어옴] 차 생성(Create)
   → 회전방향·차종 정하기(Assign)
   → 진입로 주행(Route) → 정지선 도착
   → 신호 기다리기(Hold: 초록불이면 통과)
   → 교차로 빠져나가기(Process: 줄지어 빠지는 시간)
   → 진출로 주행(Route) → [나감] 소멸(Dispose)
```

이 길을 **진입로 8개(교차로 2개 × 4개)** 에 똑같이 만들면 됩니다.

## 1. Create — 차 만들기 (진입로 8개)

진입로마다 Create 블록 1개. 차가 시간에 따라 **들쭉날쭉** 오므로, 1시간을 통째로 평균 내지 않고
**5분 단위**로 도착률을 바꿔줍니다(파일 `leg_arrival_5min.csv`의 `arrival_per_min` = 분당 도착 대수).

## 3. Hold — 신호등 (빨간불에 세우기)

가장 핵심입니다. **초록불이면 보내고, 빨간불이면 세웁니다.**

- 이동류마다 "지금 초록불인가?"를 나타내는 스위치 변수 `Green[이동류]`(1=초록, 0=빨강)를 둡니다.
- Hold 블록을 **"조건 감시(Scan): `Green[이동류]==1` 일 때 통과"** 로 설정합니다.
- 이 스위치를 켜고 끄는 **신호 담당 로직**을 따로 만듭니다. 파일 `signal_schedule_arena.csv`에는
  이동류별로 "몇 초에 초록(1)", "몇 초에 빨강(0)"이 시간순으로 적혀 있습니다(총 1,298개 사건).
  담당 로직이 이 순서대로 시간을 기다렸다가 스위치를 바꿔주면 됩니다.
- **우회전은 보통 신호 없이 상시 통행**입니다(특히 교차로15). 이런 이동류는 Hold 없이 바로 통과시킵니다.
- 두 교차로가 같은 0초(오전 8시)에서 출발하므로, 실제 **신호 시차**가 저절로 맞아 연동이 표현됩니다.

## 4. Process — 교차로 빠져나가는 시간

초록불이 켜져도 차들이 한꺼번에 순간이동하진 않습니다. **줄 서서 차례로** 빠져나갑니다.
이 "빠지는 속도"를 교통공학 표준값으로 가정합니다. (실측 통과시간 데이터가 없어서 표준을 씁니다.)

- 표준: 차로 1개가 **1시간에 약 1,900대** 처리 → 차 한 대당 약 **1.9초** 간격으로 빠짐.
- Arena 설정: **자원 잡기(Seize, 동시에 처리 가능한 수 = 차로 수) → 1.9초 대기(Delay) → 자원 놓기(Release)**
- 값은 `leg_service_params.csv`에 이동류별로 정리돼 있습니다.
  - 직진: 차로 4개 → 초당 약 2.1대
  - 좌회전·우회전: 차로 1개 → 초당 약 0.5대

## 5. Station / Route — 화면 배치와 주행

차가 화면에서 도로를 따라 움직이게 하려면 **지점(Station)** 과 **경로(Route)** 가 필요합니다.

- **배치 좌표**: `layout_coords.csv`의 `screen_x/y`(0~100)로 두 교차로 중심과 진입로 8곳을
  **실제 위치 비율 그대로** 찍습니다. (두 교차로는 실제로 약 430m 떨어져 있어 화면에서도 멀리 떨어집니다.
  세부가 잘 안 보이면 교차로별로 **확대 그림**을 따로 두면 됩니다.)
- **주행 시간**: `layout_routes.csv`의 진입/진출 주행 시간(초). 진입로가 짧아 시간이 짧게 나오는데,
  보기 좋게 길게 늘려도 결과(숫자)에는 영향 없습니다.

## 7. 돌려보고 확인하기

- **예열 구간(warm-up)**: 처음 5~10분은 도로가 텅 빈 상태라 결과가 왜곡되니, 통계에서 제외합니다.
- **여러 번 돌리기(replication)**: 같은 모델을 여러 번(예: 10번) 돌려 평균을 봅니다.
- **실제와 비교** (`validation_targets.csv`):
  - 통과량: 모델이 내보낸 대수 ≈ 실제 `vehicle_count` (오차 10% 이내면 양호)
  - 속도·지체·대기: 모델 결과가 `avg_speed`·`avg_delay`·`queue_ratio`와 비슷한 추세인지
- **눈으로 확인**: 차가 들어와 → 정지선에서 줄 서고 → 초록불에 빠지고 → 회전 방향대로 나가는지,
  신호 색이 초록불 시간과 맞는지.

### 검증 숫자 단위 (비교 전에 꼭 확인)
- `avg_speed`(속도) = **초당 미터(m/s)**. 시속으로 보려면 ×3.6.
- `queue_ratio`(대기 비율) = **0~1 사이 비율**.
- `avg_delay`(지체) = 단위가 **분명치 않음**(분 또는 0~1 비율로 추정). 정확한 지체 비교 전에
  원본 처리 코드(`src/traffic_pipeline.py`)에서 단위를 확인하세요. 그 전엔 "크다/작다 추세"만 비교 권장.

## 8. 이 모델의 한계 (보고서에 적어두세요)

우리 모델은 **차를 한 교차로에서 옆 교차로로 직접 넘기지 않습니다.** 각 교차로를 실제 관측 도착으로
따로 돌리고, 신호 시차만 공유합니다. 그래서:

- **신호 시차를 바꿔도** 옆 교차로 도착이 따라 바뀌진 않습니다(시차 최적화 실험은 이 모델로는 못 함).
- 나가는 도로 너머의 정체는 다루지 않습니다(나가면 그냥 사라짐).
- 황색·전적색 같은 손실시간은 생략(초록불만 통행). 우회전은 신호 없이 통행으로 가정.

**왜 이렇게 단순화했나?** 교차로 15와 16은 서로 다른 카메라로 측정한 별개 데이터라, "15에서 나간 차
수"와 "16에 들어온 차 수"가 실제로 안 맞습니다(약 2배 차이). 차를 직접 넘기는 모델은 이 숫자가 맞아야
하는데 안 맞아 보정이 필요합니다. 그래서 **각 교차로를 관측값 그대로 돌리는 단순·확실한 방식**을 택했습니다.

## 9. 개선안 적용하기 (병목 완화 시나리오)

병목을 줄이는 개선안을 **모델을 다시 그리지 않고 입력만 바꿔** 비교할 수 있습니다.
그러려면 **신호·차로 수를 블록에 직접 적지 말고, 위에서 만든 데이터 파일을 읽어 쓰도록** 만드세요.

- **신호 타이밍 바꾸기 (현시/주기)**: `signal_cycle_template.csv`에 현시별 녹색 길이가 있습니다.
  여기서 "좌회전 녹색 +10초" 같이 길이를 바꿔 새 신호 스케줄을 만들면 됩니다.
  (교차로15는 주요 현시 5개·주기 약 300초, 교차로16은 4개·주기 약 240초)
- **차로 수 바꾸기**: `config/lane_overrides_<이름>.json`에 `{"이동류키": 차로수}`를 적고
  `python src/14_make_service_params.py <이름>` 을 실행하면 차로 수만 바뀐
